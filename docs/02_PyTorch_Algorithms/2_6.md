# Group 2.6: Inference Execution and Generation Acceleration | 2.6：推理执行与生成加速

本组从单次 Attention 执行进入单请求生成，再比较投机式生成的不同候选拓扑。学习重点是区分“如何执行一次前向”“如何选择下一个 Token”和“如何用草稿减少目标模型轮次”。

| [INF-EXECUTION-DISPATCH](./INF-EXECUTION-DISPATCH_Inference_Fusion_and_Backend_Dispatch.md) | 融合候选、backend 能力门槛与回退 | 单卡执行路径与 profiler 证据 |

## Learning Path | 学习路径

### Recommended Order | 推荐顺序

- 执行路径：20 → `INF-EXECUTION-DISPATCH`，先确认 Attention 数据流，再判断优化候选是否真正命中 backend。
- 生成路径：21 → 23，先固定单步解码和精确验证语义。
- 草稿分支：35 / `INF-EAGLE` / `INF-PARALLEL-DRAFTING` 并列学习，再由 `INF-PROPOSAL` 统一候选预算和净收益。

### Next Steps | 后续衔接

- 多请求的 KV 状态、动态批次与阶段调度进入 [2.7](./2_7.md)。
- 真实投机生成由 [68](./68_Speculative_Decoding_Benchmark.md) 承接；项目页不重新定义本组机制。

## Environment Notes | 环境说明

- Step1–4 默认使用 CPU 建立机制和状态不变量。
- 只有 20 与已登记的真实模型路径使用单卡机制 Profile；合成 logits 或随机矩阵不作为 GPU 性能证据。
