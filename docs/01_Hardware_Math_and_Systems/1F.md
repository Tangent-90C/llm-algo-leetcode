# Group 1F: Hardware Adaptation and System Constraints | 1F: 硬件适配与系统约束

本组回答“一个模型候选为什么未必能在目标设备与运行时上交付”的问题。学习者将把芯片能力、软件栈、资源隔离、成本和运行时兼容放回同一条判断链：`设备能力 → artifact / 算子 / runtime 约束 → 资源隔离与迁移成本 → 可执行性判断`。

## Group Goal | 组定位与学习目标

本组不比较设备品牌，也不替代部署专题中的 backend 实验。它提供部署前的共同语言：CPU、GPU、NPU、TPU 等设备分别受哪些内存、精度、算子、编译、通信和运维约束；一个候选需要满足哪些条件，才值得进入真实 backend benchmark。

## Input from Compilers and Backends | 接收编译与后端约束

硬件适配不是只核对显存和 dtype。来自 [1E 编译与后端](./1E.md) 的图结构、shape、lowering 和 backend 特性，必须与设备能力共同通过检查，才能成为可部署候选。

| 1E 的执行路径信息 | 1F 的判断 | 后续验证 |
|:---|:---|:---|
| 图与 shape specialization | 目标 runtime 是否能够加载并处理同类请求 | [34](./34_Heterogeneous_Accelerators_and_Runtime_Constraints.md) |
| fusion / kernel 路径 | 目标设备是否原生支持，或会触发 fallback | [部署专题 07](../topic_discussion/deployment_heterogeneous/07_accelerator_runtime_compatibility.md) |
| backend 版本与插件依赖 | driver、compiler、runtime 是否形成一致组合 | 固定 workload 的加载日志与结果 JSON |

完成本组后，进入[部署与异构系统专题](../topic_discussion/deployment_heterogeneous/intro.md)的 Task2–6，把可行候选放入 backend、服务拓扑和 workload 证据中验证。

## Environment Notes | 环境说明

- 默认按 `CPU-first` 完成设备能力、兼容性和成本判断；不把模拟分数当作真实设备性能。
- 真实 GPU / NPU / TPU 的 runtime、算子路径和性能，需要在目标设备与固定 workload 上复测。
