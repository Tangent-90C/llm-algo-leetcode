# 后训练优化专题术语表

全教程写作遵循[术语表与中英文写作规范](../../terminology.md)。本表集中解释后训练链路中的数据、目标、状态和项目术语。

| 中文主称 | 英文 / 缩写 | 本专题含义 | 容易混淆之处 |
|:---|:---|:---|:---|
| 基础模型 | base model | 完成预训练、尚未针对目标行为完成后训练的模型 | 不等于经过 SFT 的行为基线 |
| 提示与回复 | prompt / response | 模型输入上下文与目标或生成内容 | 代码字段、数据 schema 可保留 `prompt`、`response` |
| 监督微调 | SFT | 用指令—回答监督信号训练下一个 token 预测 | 属于后训练，但训练控制机制与预训练共用 |
| 标签与标签掩码 | labels / label masking | 指定哪些 token 进入监督损失，并将提示、填充等位置标为忽略 | Attention mask 控制可见性，`labels` 控制损失位置 |
| 损失 | loss | 当前训练目标在一个批次上的数值 | 损失下降不自动代表独立任务质量提升 |
| 参数高效微调 | PEFT | 只训练少量新增或选定参数 | LoRA 是 PEFT 的一种，不等于所有低资源训练 |
| 适配器 | adapter | 与基座分离保存的可训练增量参数 | 合并后的权重与独立 adapter 是不同产物 |
| 检查点 | checkpoint | 可恢复训练或复现模型状态的保存点 | 只有模型权重而缺少优化器、调度器和进度时不一定可恢复 |
| 产物 | artifact | 模型、适配器、配置、清单和哈希等可交付文件集合 | 不只是一份权重文件 |
| 基线与候选 | baseline / candidate | 在固定工作负载中被比较的现有方案与待验证方案 | “新模型”不自动是候选，必须固定身份和比较条件 |
| 偏好对 | preference pair | 同一提示下的优选回答（`chosen`）与非优选回答（`rejected`） | 两条回答必须共享比较口径与 token 范围 |
| 策略 | policy | 生成回复或轨迹并接受更新的模型 | 与部署服务实例、参考策略和旧策略快照区分 |
| 参考策略 | reference policy | 为偏好目标提供相对约束的固定策略 | 不等于 rollout 时的旧策略快照 |
| 行为策略 / 旧策略 | behavior policy / old policy | 实际生成当前轨迹、或更新前保存的策略快照 | 参考策略提供长期约束；旧策略用于计算当前更新相对采样策略的变化 |
| 策略比率 | policy ratio | 当前策略与旧策略对同一动作概率之比 | 不是模型质量分数；PPO 用它限制单次更新幅度 |
| KL 散度与 KL 约束 | KL divergence / KL penalty | 衡量当前策略相对参考策略的分布偏离，并作为训练约束 | 不能修复错误奖励或污染数据；系数变化需要固定工作负载复测 |
| 奖励 | reward | 环境、规则验证器或奖励模型给出的任务反馈 | 奖励不等于训练损失，也不自动代表真实任务质量 |
| 奖励塑形 | reward shaping | 将正确性、格式、长度、KL 等多个信号组合为更新反馈 | 各分量必须分别记录，避免总奖励掩盖奖励投机 |
| 终止奖励与逐 Token 奖励 | terminal / token-level reward | 分别在轨迹结束时或每个生成位置提供反馈 | 奖励放置位置会改变回报和优势的传播方式 |
| 奖励模型 | reward model | 将轨迹或回答映射为标量偏好信号 | 奖励不等于价值，价值是期望回报基线 |
| 回报 | return | 从当前位置开始累计的后续奖励 | 与单步奖励、最终任务分数区分 |
| 价值与价值模型 | value / Critic | 对状态未来回报的估计及其模型 | Critic 输出 value，不直接替代奖励模型 |
| 优势 | advantage | 回报相对基线的更新信号 | PPO 可用 value 基线，GRPO 可用组内基线 |
| 组内基线 | group baseline | 用同一提示下候选奖励的组内统计量构造相对优势 | 组内奖励方差接近零时，更新信号会退化 |
| 轨迹 / 采样记录 | rollout | 带策略版本、token、动作、奖励和状态的采样记录 | 不只是最终提示—回复文本；过程名称也可写 rollout |
| 采样批次与更新批次 | rollout batch / update batch | 分别表示一次生成收集的轨迹集合和一次参数更新消费的数据集合 | 两者大小、切分和版本可以不同，必须通过轨迹身份关联 |
| 策略新鲜度 | policy freshness | 轨迹策略版本与当前 learner 版本的差距 | 文件时间不能替代策略版本 |
| 策略滞后 | policy lag / staleness | 轨迹生成版本落后于当前学习器版本的程度 | 新鲜度是准入条件，滞后是需要度量和限制的差值 |
| 同策略与异策略 | on-policy / off-policy | 轨迹是否由当前待更新策略或其他历史策略产生 | 不能只凭数据文件的新旧判断，必须检查策略版本 |
| 验证器 | verifier | 用规则、执行结果或环境终态检查回答或轨迹 | 能验证编码规则，不保证覆盖完整质量 |
| 模型评审器 | Judge / LLM-as-a-Judge | 使用模型按固定 rubric 比较或评分输出 | 需要记录模型、提示、顺序和一致性，不能当作绝对真值 |
| 学习器与工作进程 | learner / worker | 执行参数更新的角色与承担采样、奖励等阶段的进程 | 角色、进程和物理 GPU 不是同一层概念 |
| 共置与解耦部署 | colocated / disaggregated | 采样、奖励和更新角色共享或拆分计算资源的系统拓扑 | 是资源与调度选择，不改变奖励和优势的数学定义 |
| 可验证奖励强化学习 | RLVR | 使用规则、执行器或 verifier 产生可检查奖励 | 可验证不代表奖励设计没有漏洞 |
| 回滚门槛 | rollback gate | 安全、质量或稳定性退化时撤回候选 | 训练 loss 改善不能绕过回滚条件 |

## 使用规则

- 首次出现使用“中文主称（English）”，后续使用中文主称或通用缩写。
- `SFT`、`LoRA`、`QLoRA`、`DPO`、`PPO`、`GRPO`、`RLVR` 可直接使用；普通叙述优先使用“基线、候选、工作负载、产物、执行后端”。
- `prompt`、`response`、`labels`、`chosen`、`rejected`、`reward` 等只在代码字段、公式、JSON 或首次释义中保留；连续中文叙述使用“提示、回复、标签、优选回答、非优选回答、奖励”。
- `policy`、`reference`、`rollout`、`judge`、`verifier`、`checkpoint`、`artifact` 在首次出现时给出中文主称，后续优先使用中文；框架类名和 API 不翻译。
- `old_policy`、`policy_ratio`、`kl_coef`、`rollout_batch` 等代码字段保持原名；正文分别写“旧策略”“策略比率”“KL 系数”和“采样批次”。
- 数据版本、策略版本、模型 revision 和产物 hash 分开记录，不用“版本一致”概括。
- 不对 Notebook JSON、代码变量和框架 API 做无上下文批量替换。
