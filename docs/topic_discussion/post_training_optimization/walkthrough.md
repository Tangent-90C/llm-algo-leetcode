# 后训练优化问题链 | Post-Training Walkthrough

后训练先建立共同基线，再根据反馈形态进入不同分支，而不是依次套用 SFT、DPO、PPO 和 GRPO。下面始终跟踪同一个对象：一条用户提示及其回答，观察它怎样从监督样本变成偏好对、带奖励的轨迹和最终评测证据。

`提示与目标 → 监督样本与 SFT 基线 → 偏好对或奖励轨迹 → 策略更新 → 独立评测与决策`

## 一、先选阶段，再确定目标

先为目标任务固定一组提示和独立评测样本，判断失败来自指令表达、外部知识还是模型行为。提示工程、RAG 或工具调用已经能稳定解决的问题不必立即训练；确需改变模型行为时，再选择 SFT、偏好优化或强化学习。

对应 [00 后训练全景与阶段选择](./00_post_training_landscape.md)。

## 二、把数据变成可靠监督

同一条提示与目标回答进入聊天模板后形成 `input_ids`、注意力掩码和标签。标签掩码决定哪些 Token 进入监督损失；样本身份、数据切分、去重和去污染决定这条监督能否进入训练池。这里的产物不是一段文本，而是一批可追踪、监督范围明确的训练样本。

对应 [01 SFT 数据与监督契约](./01_sft_data_and_loss.md)。

## 三、建立可复查的 SFT 基线

LoRA 决定哪些参数可更新，训练控制决定何时完成一次有效更新，实验交付保存检查点、适配器、分词器、配置和评测结果。对同一条提示，SFT 基线至少要能稳定生成符合任务接口的回答，后续偏好或奖励分支才有可比较的起点。

对应 [02 LoRA / PEFT](./02_lora_peft_design.md)、[03 训练控制](./03_training_control.md) 与 [04 SFT 实验与交付](./04_end_to_end_experiment.md)。

## 四、根据反馈形态选择优化方法

若同一提示已有可复查的优选回答和非优选回答，可进入 DPO。若需要让当前策略生成新候选并获得显式奖励，可选择 PPO；同一提示能够生成多个候选且奖励可比较时，可选择 GRPO / RLVR。三条路径都从同一 SFT 基线出发，但消费的数据和更新信号不同。

| 分支 | 同一提示产生的训练对象 | 更新依据 |
|:---|:---|:---|
| DPO | 优选回答、非优选回答、参考策略概率 | 相对偏好边际 |
| PPO | 旧策略轨迹、奖励、价值、当前与旧策略概率 | 优势、策略比率与 KL 约束 |
| GRPO / RLVR | 同一提示的候选组与逐候选奖励 | 组内相对优势与 KL 约束 |

对应 [05 DPO](./05_dpo_and_preference_optimization.md)、[06 PPO / RLHF](./06_rlhf_and_ppo_system_cost.md) 与 [07 GRPO / RLVR](./07_grpo_and_groupwise_alignment.md)。

## 五、把算法接回训练与生成系统

强化学习需要把轨迹采样、奖励或验证器、参数更新与评测拆成可测阶段。每条轨迹记录提示、回复 Token、行为策略版本、奖励分量和消费状态；学习器只接纳满足策略新鲜度条件的轨迹。需要多工作进程编排时进入 RL 系统分支，需要持续收集偏好并更新策略时进入在线 DPO 分支。

`TRL` 适合机制和小规模闭环；需要更重的轨迹采样与资源编排时，再依据实验条件选择 `verl`、OpenRLHF、vLLM / SGLang 与 Ray。

对应 [08 RL 工程与效率](./08_rl_engineering_and_efficiency.md)。

## 六、用独立评测和回滚条件收口

训练损失、奖励或胜率上升都不足以直接采用。回到开头冻结的提示和评测样本，对基线与候选执行相同解码与评分协议，再结合任务正确性、安全、鲁棒性、模型评审器一致性、资源成本和失败样本，给出 `accept / tune / reject`。

对应 [09 评测、反馈与项目决策](./09_preference_data_and_project_decision.md)。
