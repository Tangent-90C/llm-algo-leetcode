# 01 · 推理服务综合项目

> 项目类型：综合项目　项目分组：5.1 核心交付项目

## 项目定位

本项目把推理优化、性能优化、量化与部署专题中的方法组合起来，完成一个可复查的推理服务方案。重点不是单独实现某个算子或替换某个推理后端，而是回答：在给定模型、请求流量、硬件和质量约束下，怎样选择方案并证明它值得交付。

项目结论应同时覆盖请求性能、显存容量、输出质量、运行稳定性和单位成本，不能只依据一次吞吐结果。

## 项目问题

给定一个目标模型和一组代表性请求，比较固定基线与候选推理方案，形成最终的 `accept / tune / reject` 决策。

至少需要明确：

- 模型与权重格式：模型规模、dtype、量化格式和最大上下文长度；
- 服务条件：硬件、推理后端、并发、请求长度、输出长度和调度策略；
- 质量要求：任务质量、数值误差、拒答或格式约束；
- 性能目标：TTFT、TPOT、P50/P99、吞吐和峰值显存；
- 交付约束：启动方式、依赖版本、回滚方案和复现实验入口。

## 推荐项目流程

```text
定义工作负载
  → 建立服务基线
  → 分析 Prefill / Decode / KV Cache
  → 选择候选优化组合
  → 进行 CPU 机制验证与真实服务基准测试
  → 检查质量、稳定性和容量边界
  → 估算单位成本
  → 输出部署决策
```

## 建议的候选方案

候选方案不要求全部实现，应根据基线证据选择能够解释瓶颈的方案：

| 候选方向 | 主要解决的问题 | 需要同时观察的代价 |
|:---|:---|:---|
| KV Cache 管理与分页 | 并发容量、碎片和缓存复用 | 命中率、维护开销、TTFT 与质量 |
| Prefix Cache / 请求复用 | 共享前缀带来的重复计算 | 命中率、最长前缀、调度复杂度 |
| Continuous Batching | 请求到达不均和 GPU 空闲 | 排队时间、P99、调度开销 |
| 量化与低精度执行 | 权重容量、带宽和吞吐 | 质量变化、目标内核与推理后端支持 |
| 推理后端或引擎切换 | 调度、算子和运行时效率 | 兼容性、启动成本、维护与回滚 |
| Prefill / Decode 分离 | 不同阶段的资源冲突 | 通信、同步、部署复杂度和成本 |

## 异构硬件与多模型扩展

当文本服务基线稳定后，可以在同一请求协议下比较模型、精度、推理后端或硬件中的一个主要变量。候选模型族和运行时支持会变化，因此每次实验都记录实际模型 revision、后端版本和设备身份，不把某个产品名称或 API 当作长期不变的前提。

| 实验组 | 受控变化 | 要回答的问题 | 最小交付物 |
|:---|:---|:---|:---|
| G0 · 文本基线 | 固定模型、硬件、精度和后端 | 当前服务是否可以稳定启动并满足基础质量要求？ | 启动记录、请求结果、基线指标与失败记录 |
| G1 · 单变量候选 | 只替换模型、精度、后端或硬件中的一项 | 收益来自哪个变化，是否引入兼容性或质量代价？ | 配对指标、能力检查与候选产物清单 |
| G2 · 路由或分离部署 | 增加多模型路由、多模态请求或阶段分离 | 额外系统复杂度是否换来可验证的服务收益？ | 路由记录、降级路径、长尾延迟与回滚证据 |

文本、OCR、图像或语音请求共用一份请求身份和失败状态；不支持的能力必须进入明确的降级路径。多模型与多模态对照只有在 G0 可复测、G1 的单变量影响已经解释后才进入 G2，避免同时改变模型、硬件与路由而无法归因。

每次运行至少保存工作负载、模型、硬件、推理后端、指标、失败和决策七类信息。字段名可以由具体项目 schema 定义，但基线与候选必须使用同一 schema 和单位。

## 证据要求

### 基线与工作负载

基线和候选必须使用同一模型、请求集、硬件、数据类型、预热次数、并发和重复次数。每次实验至少保存配置、版本、日志和结果 JSON，避免只记录最终均值。

### 核心指标

| 证据类别 | 最少记录的指标 | 用途 |
|:---|:---|:---|
| 请求性能 | TTFT、TPOT、端到端延迟、P50/P95/P99 | 判断交互体验与长尾风险 |
| 服务吞吐 | output tokens/s、request/s、有效完成量 | 判断资源利用和容量收益 |
| 显存与容量 | 峰值显存、KV Cache 占用、并发上限、OOM 边界 | 判断方案是否真正扩大服务容量 |
| 阶段归因 | Prefill、Decode、排队、通信和同步时间 | 解释收益来自哪里、代价转移到哪里 |
| 质量与稳定性 | 质量集、错误率、超时率、结果一致性 | 防止性能收益掩盖功能回归 |
| 成本 | GPU 时间、单位请求成本、单位输出 token 成本 | 支持最终部署与 TCO 决策 |

## 最终交付物

项目至少包含以下交付物：

1. 一份工作负载、环境和版本清单；
2. 一份基线 / 候选对照表；
3. 一份显存、延迟、吞吐和质量证据记录；
4. 一份瓶颈归因与失败实验记录；
5. 一份候选方案成本和维护代价比较；
6. 一项明确的 `accept / tune / reject` 决策，以及适用条件和回滚路径。
