# 第五部分：综合项目与架构决策

> 综合决策层：把多条主学习路线的证据汇总为可交付的系统方案。

## 本部分定位

Part 05 不再新增一条单独技术路线，也不替代推理、性能、算子或后训练专题。它负责把这些路线中的机制、基准测试、质量结果和工程约束放到同一个项目问题中，完成方案组合与架构决策。

## 推荐学习方式

先从一个明确的系统目标开始，再回查相关主路线和横向专题：

```text
目标与约束 → 固定基线 → 瓶颈证据 → 候选组合 → 对照实验 → 成本与质量 → 架构决策
```

Part 05 按项目与主学习路线的稳定关系分为“核心交付项目”和“开放实践项目”。前者承担稳定的跨专题交付链，后者允许围绕新场景、框架或硬件灵活扩展；两组都要从明确目标和约束出发，形成可复测证据与明确决策。

## 5.1 核心交付项目

本组收录与专题 Task、Part 02 项目链和统一证据契约稳定连接的综合项目。项目跨越多个 Part 和主学习路线，重点不是重复讲某个局部机制，而是把目标、约束、实现、实验和交付结果连接为可复查的交付链。

| 项目方向 | 主要组合的路线 | 需要形成的结果 |
|:---|:---|:---|
| [推理服务综合项目](./01_Inference_Service_Integrated_Project.md) | 推理优化、性能优化、量化与部署 | 请求链路、推理后端、KV Cache、延迟吞吐和服务质量的综合结论 |
| [后训练交付综合项目](./02_Post_Training_Delivery_Project.md) | 后训练优化、性能优化、通信并行、量化与数据工程 | 数据、训练、评测、资源与模型产物的闭环决策 |

每个项目至少应保留：问题定义、环境与工作负载、固定基线、候选方案、实测证据、质量结果、限制条件和最终决策。

Part 02 项目与 Part 05 项目承担不同职责。机制小节先验证局部关系，Part 02 项目再验证固定工作负载下的单一交付链；Part 05 读取这些项目产物，比较跨专题候选的服务目标、质量、成本、可靠性和回滚条件。以量化为例，产物准入、量化部署和服务性能分析先在 Part 02 分别形成证据，推理服务综合项目再把它们与缓存、调度和推理后端方案共同复测。

阅读时先选择一个综合项目，按项目页给出的输入资产和固定工作负载完成对照，再使用本页后半部分的共同决策框架解释硬件、引擎、部署拓扑与成本选择。Agentic RL 作为[后训练交付综合项目](./02_Post_Training_Delivery_Project.md#小模型-agentic-rl-扩展)中的可选扩展，不是所有后训练交付的必经阶段。

## 5.2 开放实践项目

本组用于承接更灵活的真实场景，例如新模型或硬件适配、竞赛任务、行业数据、端侧部署、多模态服务和智能体应用。项目不要求覆盖一条完整主学习路线，但必须写明项目目标、依赖的机制、工作负载、复测入口和适用条件。

开放实践项目至少保留可运行基线、一个可解释候选、质量或正确性检查、资源记录和失败状态。项目形成稳定的跨专题依赖、统一结果契约和持续复测入口后，可以转入 5.1；只有想法而没有页面或执行入口时，不建立占位项目。

## 共同决策框架

综合项目不从单个实现细节直接作结论，而是回答“在给定目标、预算和约束下，应该选择什么方案”。

| 决策方向 | 主要比较对象 | 典型输出 |
|:---|:---|:---|
| 硬件选型决策框架 | GPU、CPU、互连、显存和带宽 | 容量、性能、扩展性与采购约束的比较 |
| 架构选型决策框架 | 单体、分层、服务化和多阶段架构 | 延迟、吞吐、可靠性和维护复杂度的权衡 |
| 引擎选型决策框架 | vLLM、SGLang、TensorRT-LLM 等 | 工作负载、推理后端能力、生态和证据质量的比较 |
| 部署架构选型决策框架 | 单机、多卡、多节点和异构部署 | 部署拓扑、资源隔离、扩缩容和故障恢复方案 |
| 成本模型与 TCO 分析 | 设备、运行、通信、存储和维护成本 | 单请求成本、单位吞吐成本、回本周期和敏感性分析 |

决策结论必须引用具体综合项目或前置专题中的证据，不能只依据理论峰值或单项基准测试。

## 综合项目关注的问题

| 维度 | 需要回答的问题 | 典型证据 |
|:---|:---|:---|
| 性能 | 端到端延迟、吞吐和扩展效率是否达到目标？ | 基准测试、P50/P99、吞吐与执行轨迹 |
| 显存与容量 | 当前模型、上下文和并发是否能稳定运行？ | 峰值显存、KV Cache、显存溢出边界、容量账本 |
| 质量 | 优化是否改变输出、训练稳定性或任务指标？ | 质量集、回归测试、数值误差、偏好指标 |
| 成本 | 设备、运行时间、通信和维护成本如何变化？ | 成本模型、资源利用率、容量规划 |
| 交付 | 模型产物、推理后端、环境和回滚路径是否完整？ | 产物、配置、启动记录与 `accept / tune / reject` |

## 与前面路线的关系

- 推理优化提供请求链路、KV Cache、服务调度和推理后端方案。
- 性能优化提供性能分析、显存、通信、I/O 和成本证据。
- 算子优化提供 Kernel、Fusion、访存和执行路径方案。
- 后训练优化提供模型能力、数据质量和对齐结果。
- 量化、通信并行、部署与异构等横向专题提供具体约束和扩展方案。

## 何时需要新的综合项目

新的综合项目仍按“场景目标—约束条件—候选架构—实验证据—交付决策”组织。只有当多个专题的产物需要在同一工作负载下共同决定服务或训练交付时，才需要独立的 Part 05 项目；单个局部指标改善不能直接作为系统级结论。
