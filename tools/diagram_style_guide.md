# SVG 制图组件与颜色规范

本文件是教程 SVG 的轻量组件参考。它不要求所有图片使用同一套布局，但要求颜色语义、文字层级和箭头行为保持一致。

## 生成前检查

新建或重绘图片时，不能脱离所在页面单独决定画布。开始写 SVG 前依次完成：

1. 读取目标页面及同页已有图片，确认新图承担主图、补充机制图、实验流程图、矩阵还是时间线；先写出这张图要回答的唯一问题。
2. 若同页已有同角色图片，直接继承其 `width`、`height`、`viewBox`、标题带、外边距、字号、节点高度、线宽和箭头规格，不重新发明一套尺寸。
3. 同页没有可继承样板时，横向流程图默认使用 `1240 × 600`；矩阵、树和时间线可使用独立比例，但应先记录采用该比例的结构原因。
4. 先列节点与边：每个节点只承担一个概念，每条边写明数据流、依赖、反馈或可选关系；没有语义关系的并列节点不加箭头。
5. 预估内容占用边界。左右有效内容通常覆盖画布宽度的 80%–92%，首层和末层留白与同页图片接近；不能因为节点少就放大字号和节点，也不能靠大面积空白缩小主图。

生成提示或维护任务必须包含“目标页面、图片角色、继承的图族规格、节点清单、边语义、例外理由和验收命令”七项。缺少其中任一项时，先补设计信息，不直接生成图片。

## 最小画布骨架

```svg
<svg xmlns="http://www.w3.org/2000/svg"
     width="1240" height="600" viewBox="0 0 1240 600"
     role="img"
     aria-labelledby="title desc">
  <title id="title">中文图片标题</title>
  <desc id="desc">用一句话描述图片展示的关系。</desc>
  <defs>
    <marker id="arrow" markerWidth="10" markerHeight="10"
            refX="8" refY="3" orient="auto">
      <path d="M0,0 L9,3 L0,6 Z" fill="#475569" />
    </marker>
  </defs>
  <rect width="1240" height="600" fill="#F8FAFC" />
</svg>
```

## 组件约定

```css
/* 标题、节点标题、节点正文、辅助说明 */
.title { font-size: 25px; font-weight: 700; }
.heading { font-size: 18px; font-weight: 700; }
.body { font-size: 15px; font-weight: 500; }
.small { font-size: 14px; font-weight: 500; }

/* 节点和连线 */
.node { stroke-width: 2; rx: 14; }
.flow { stroke: #475569; stroke-width: 2.5; fill: none;
        marker-end: url(#arrow); }
.support { stroke: #94A3B8; stroke-width: 2; fill: none;
           stroke-dasharray: 7 6; marker-end: url(#arrow); }
```

字体优先使用：

```css
font-family: "Noto Sans CJK SC", "Microsoft YaHei", sans-serif;
```

## 使用规则

1. 主图回答“这些概念如何联系”；第二图回答“如何实验、比较或决策”。
2. 一个节点尽量只有概念名和一行解释；字段列表、参数和结果放 Markdown 表格。
3. 采用总分结构，不在图片底部重复增加总结节点。
4. 连接线不能穿过节点或文字；分支尽量使用直线，必要时扩大节点间距。
5. SVG 只表达结构关系，不表达未经实测的速度、显存或质量收益。
6. 修改后至少运行 XML 校验、路径检查和 `git diff --check`。
7. 同一页面的一组横向图片默认采用相同画布、宽高比、标题带、字号和节点尺度；矩阵或时间线确需例外时保留独立比例，但必须通过页面级尺度审计。

## 节点、连线与箭头尺度

以下数值以默认 `1240 × 600` 横向画布为基准；其他画布按短边比例缩放。时间线、矩阵或树形图确需突破范围时，必须说明结构原因，并继续满足同页尺度审计。

1. 普通概念节点建议宽 `180–280`、高 `68–96`；只有一个短标签的紧凑节点可缩到宽 `140–180`。单个普通节点不应占画布宽度的 30% 以上。
2. 同层同角色节点优先使用相同宽高。文字放不下时先缩短文案或增加节点宽度，不通过增大整张图或把节点高度翻倍解决。
3. 主流程连线默认 `stroke-width: 2.5`，辅助关系默认 `2`；除坐标轴、时间轴或明确强调的主干外，不使用大于 `3` 的线宽。
4. 普通箭头统一使用 `8–10` 的 `markerWidth/markerHeight`；不得用大于 `12` 的 marker 补偿连线不可见问题。同一张图的同类连线必须共用箭头规格。
5. 正交连线转折后至少保留 `24px` 或两倍 marker 宽度的直线段，再放置箭头；若空间不足，应移动节点或改变锚点，不让大箭头紧贴转角。
6. 节点缩放、线宽和箭头必须一起检查。禁止只放大箭头或加粗连线来掩盖悬空、未连接或路由错误。

## 箭头与连线路由规则

1. 一条语义关系必须使用一个独立的 `<path>`、`<line>` 或 `<polyline>`；禁止在一个带 `marker-end` 的 `<path>` 中用多个 `M/m` 拼接多条边。不同浏览器可能只在整条 path 的最后一个子路径绘制箭头。
2. 连线起点和终点使用节点边界的明确锚点（左、右、上、下中点），不得停在节点内部、悬空在边框外，或依赖视觉上“差不多对齐”的坐标。
3. 主流程优先采用水平或垂直的正交路径。转折发生在节点间留白区域；不得穿过节点、组标题、连线文字或无关分组。
4. 箭头只放在目标端。普通主流程使用 `markerWidth/markerHeight: 8–10`、`refX` 靠近箭头尖端和 `stroke-width: 2.5`；缩放后的例外仍须遵守上一节的比例与上限，避免箭头不可见或压过节点。
5. SVG 中先绘制分组背景和连线，再绘制节点时，终点应停在边框外并由 marker 尖端接触边框；若节点先于连线绘制，则连线仍不得伸入节点文字区。
6. 自动检查只能发现结构错误。提交前还要按文档实际显示宽度检查：箭头可见、确实连接目标节点、路线符合数据流或因果关系。

结构检查示例：

```bash
python tools/check_svg_arrows.py docs/public/02_PyTorch_Algorithms/example.svg
python tools/check_svg_layout.py
```

`check_svg_layout.py` 将缺失 `width/height/viewBox`、画布拉伸和同页尺度异常纳入检查。存量问题记录在 `tools/svg_layout_baseline.json`；修复存量图后应删除相应 baseline 条目，不能用更新 baseline 的方式接纳新回归。
