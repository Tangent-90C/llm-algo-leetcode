# 推理优化专题术语表

全教程写作遵循[术语表与中英文写作规范](../../docs/terminology.md)。本表只解释推理语境中容易混淆的对象；代码标识符、配置键、模型名和结果 JSON 字段保留原始英文。

| 中文主称 | 英文 / 缩写 | 本专题含义 | 容易混淆之处 |
|:---|:---|:---|:---|
| 首 Token 延迟 | TTFT | 请求到达后获得首个输出 Token 的时间 | 主要受排队与 Prefill 影响，不代表 Decode 速度 |
| 每输出 Token 时间 | TPOT | Decode 阶段相邻输出 Token 的平均时间 | 与端到端延迟、吞吐不是同一指标 |
| 端到端延迟 | E2E latency | 从请求到达到完成或失败的总时间 | 必须结合输入、输出长度和终止状态解释 |
| 服务等级目标 | SLO | 为延迟、吞吐、可用性、超时率或拒绝率设定的可测目标，必须注明指标、分位数和统计窗口 | 不是单个性能指标；也不等同于包含责任条款的对外服务等级协议（SLA） |
| 预填充 | Prefill | 一次处理输入 Token 并建立初始 KV 状态 | 不等同于请求到达后的全部 TTFT |
| 解码 | Decode | 基于已有状态逐轮生成后续 Token | 与“有推理能力的模型”无关 |
| 本轮 Token 预算 | iteration token budget | 当前迭代允许处理的 Prefill 与 Decode Token 总量 | 不等同静态 batch size |
| 执行槽位 | batch slot | 当前迭代中可容纳一个活跃请求的位置 | 有空槽位不代表 KV 或 Token 预算足够 |
| 迭代边界 | iteration boundary | 一轮前向结束后释放终止请求、接纳新请求并更新批次的时点 | 不等同请求级优先级排序 |
| 连续批处理 | continuous batching | 在迭代边界移出完成请求并接纳新请求 | 请求优先级由请求级调度决定，批次成员由迭代级调度决定 |
| KV 生命周期 | KV lifecycle | KV block 的分配、追加、共享、引用、驱逐和回收 | 与请求公平性和优先级是不同问题 |
| 前缀缓存 | prefix cache | 复用相同前缀已计算的 KV 状态 | 命中率不能仅由 TTFT 变化反推 |
| 预填充—解码分离 | PD disaggregation | 将 Prefill 与 Decode 放到不同执行资源或服务层 | 分离后仍需处理 KV 交接和排队 |
| 暴露传输时间 | exposed transfer time | 无法被计算或准备工作隐藏的传输时间 | 传输总时间下降不代表暴露时间必然下降 |
| 执行分派 | backend dispatch | 根据能力门槛选择 eager、compile 或专用后端路径 | API 可调用不证明命中目标 Kernel |
| 回退 | fallback | 候选路径不满足能力或稳定性条件时使用保守路径 | 回退必须记录原因，不能静默并入候选结果 |
| 模型产物 | model artifact | 权重、配置、分词器、量化元数据和文件哈希组成的可加载交付物 | 量化算法名称不等于可被目标后端加载的产物格式 |
| 加载器 | loader | 将模型产物解析为目标执行后端可运行状态的组件 | 成功加载不证明目标低精度计算内核已经执行 |
| 计算内核路径 | kernel path | 请求实际经过的浮点、低精度或融合计算实现 | 配置中的目标数据类型不等于运行时真实路径 |
| 草稿模型 | draft / assistant model | 在目标模型验证前生成候选 Token 的轻量模型或附加模块 | 草稿输出不能绕过目标模型验证直接提交 |
| 目标模型 | target / verifier model | 验证草稿候选并决定接受、拒绝与修正的主模型 | 与奖励模型或评测模型不是同一角色 |
| 连续接受长度 | accepted prefix length | 从候选首位开始连续通过目标验证的 Token 数 | 后部命中不能跨过前部拒绝位置 |
| 候选预算 | proposal budget / speculation lookahead | 每轮允许草稿器提出并送入验证的最大候选数 | 越大不一定越快，还会增加草稿与修正成本 |

首次出现使用“中文主称（English）”，后续使用中文主称或表中通用缩写。普通叙述优先使用“工作负载、执行后端、候选、回退”；模型名、API、配置键和 JSON 字段保持原文。
