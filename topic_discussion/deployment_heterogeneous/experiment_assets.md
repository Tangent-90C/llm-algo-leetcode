# 部署与异构实验资产表

本表登记部署实验使用的环境、候选身份、工作负载、结果路径和证据状态。安装与恢复命令见[实验 Quickstart](./quickstart.md)，跨专题软件版本和硬件快照见[GPU 环境资产表](../../docs/gpu_environment_assets.md)。

## 环境角色

| 环境或角色 | 直接入口 | 可形成的证据 | 不能替代的证据 |
|:---|:---|:---|:---|
| CPU 契约验证 | 正文 01–08，Part 01 · 34 | 产物字段、能力门槛、放置、成本和回滚逻辑 | 真实加载、计算内核与服务性能 |
| `INF-VLLM-011-CU128` | Part 02 · 66、67、72、82、83 | 单卡 vLLM 加载、固定请求、延迟、吞吐、容量和失败记录 | SGLang、llama.cpp、端侧或多卡结论 |
| 量化产物环境 | 量化专题的 40、53、82 | 生成或准入 GPTQ、AWQ、W8A8 等候选产物 | 目标服务后端的执行收益 |
| 通信与并行环境 | Part 02 · 39、81 与通信专题项目 | 多设备状态布局、通信、状态交接和扩展证据 | 单卡候选的质量与产物完整性 |
| 端侧执行环境 | llama.cpp / GGUF 等独立候选 | CPU、统一内存或部分卸载路径的延迟与内存 | GPU 服务后端的吞吐排名 |

后端环境相互隔离。部署专题通过共同的模型 revision、输入协议、质量集和工作负载连接结果，不通过共享 Python 环境连接不同执行栈。

## 模型与工作负载角色

| 角色 | 默认选择 | 用途 | 结论边界 |
|:---|:---|:---|:---|
| 语义与产物基线 | `Qwen/Qwen2.5-0.5B-Instruct` | 检查模型、分词器、模板、量化产物和加载器 | 不形成生产服务性能结论 |
| 单卡服务候选 | `Qwen/Qwen3-0.6B` | vLLM 启动、固定请求、并发、容量与服务指标 | 只适用于登记的模型配置和后端版本 |
| 量化部署候选 | 82 通过准入的稳定产物引用 | 比较浮点与量化路径 | 产物生成成功不代表目标计算内核生效 |
| 多设备候选 | 81 登记的真实模型和请求集 | 比较副本、模型切分或阶段分离 | 单卡结果不能外推扩展效率 |

每次运行至少固定模型 revision、分词器与模板、输入输出长度、并发、预热、重复、质量集、设备和推理后端。模型、后端或工作负载改变后使用新的运行标签。

## 推荐验证顺序

| 顺序 | 验证对象 | 通过条件 | 失败后的动作 |
|:---|:---|:---|:---|
| 0 | CPU 契约与设备能力 | 候选身份完整，目标设备和后端没有已知阻断项 | 修复产物、输入协议或能力条件，不进入性能比较 |
| 1 | 82 产物准入 | 文件、哈希、模型 revision、质量方向和加载器检查通过 | 拒绝产物或返回量化专题重新生成 |
| 2 | 66 浮点服务基线 | 固定请求能够重复完成，质量与服务指标可记录 | 修复环境、模型或请求协议 |
| 3 | 67 或 72 单卡候选 | 与基线使用相同模型身份、请求、设备和统计方式 | 保留失败日志，检查路径回退或容量边界 |
| 4 | 83 服务配置回归 | 至少一组配置满足对应质量、容量和服务目标 | 调整配置或回退到上一稳定候选 |
| 5 | 81 多设备候选 | 单卡不足证据明确，通信、状态交接和恢复结果完整 | 不用单卡模拟替代多卡证据，保留为待验证候选 |
| 6 | Part 05 综合交付 | 候选具备成本、降级、恢复和回滚条件 | 输出调优或拒绝决定，不以局部吞吐代替交付结论 |

## 部署结果增量字段

通用结果契约之外，部署证据至少增加以下字段：

| 字段组 | 必须记录的内容 |
|:---|:---|
| 候选身份 | 模型、revision、分词器、模板、产物 ID、文件哈希与配置 |
| 执行环境 | 设备、驱动、运行时、推理后端、实际数据类型与目标计算路径 |
| 工作负载 | 输入模态、输入输出长度、并发、预热、重复、质量集版本 |
| 服务指标 | TTFT、TPOT、端到端延迟、P95/P99、吞吐、峰值显存和失败率 |
| 路径证据 | 加载器、计算内核或执行事件、回退原因、状态交接与传输等待 |
| 交付状态 | 失败、降级、恢复、回滚、证据等级与采用决定 |

环境预检、加载成功和单次请求只证明相应阶段可运行。只有固定工作负载下的重复测量、质量检查和路径证据同时完整，结果才能进入部署选型。
