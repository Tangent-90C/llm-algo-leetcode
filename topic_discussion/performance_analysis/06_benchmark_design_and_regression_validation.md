# 06 基准设计与回归验证

执行轨迹只能提出候选归因；是否保留一个优化，必须回到同一工作负载的基线 / 候选对照，并同时检查质量、波动和失败状态。

## 让基线与候选可比较

模型、输入、硬件和测量过程必须保持一致，候选策略是唯一主动变化的变量。结果表同时保留收益和代价，避免只挑最好的一次运行。

| 字段 | 对照要求 | 记录原因 |
|:---|:---|:---|
| 工作负载 | 模型、输入、批量、并发、输出长度一致 | 排除输入差异 |
| 环境 | 硬件、软件、数据类型、执行后端一致 | 排除运行路径差异 |
| 测量过程 | 预热、重复次数、统计方式一致 | 降低冷启动与噪声影响 |
| 目标指标 | 延迟、吞吐、峰值或扩展效率 | 验证原始假设 |
| 守护指标 | 质量、OOM、P99、成本或失败率 | 发现被转移的代价 |

![基准验证与回归检查](../../docs/public/topic_discussion/performance_analysis/benchmark_validation_board.svg)

## 结果如何进入下一步

候选只有在目标指标改善、守护指标未越界且重复结果稳定时，才可进入组合复测；证据不足时，应补齐基线、执行轨迹、对象驻留或瓶颈归因。
