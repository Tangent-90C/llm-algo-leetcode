# 07 从归因到行动

性能分析的终点不是一张图，而是一份能够说明“为何采取这个动作、在哪些条件下成立”的记录。行动状态描述分析进度；项目中的接受、调优或拒绝描述具体候选的工程决策，两者可以同时出现。

## 用证据决定行动

| 状态 | 需要具备的证据 | 输出 |
|:---|:---|:---|
| `inspect` | 现象存在，但指标或工作负载还不完整 | 补测字段与待验证假设 |
| `optimize` | 时间、显存或通信证据已指向目标对象 | 候选策略与预期代价 |
| `validate` | 同口径对照显示稳定收益，守护指标未越界 | 适用工作负载、复测记录与限制 |
| `revert` | 候选无收益、引入回归或无法复现 | 回退原因与下一条假设 |

## 最小结论记录

性能优化接收的是诊断记录，不是截图、热点名称或一串工具输出。记录至少固定以下字段；证据不足时保留待验证假设，不提前指定优化方案。

| 字段组 | 必须保留 | 交给性能优化的作用 |
|:---|:---|:---|
| 问题身份 | 现象、阶段、目标指标、工作负载与环境 | 保持候选复测口径不变 |
| 证据引用 | 基线分布、执行轨迹、对象驻留、性能剖析和结果路径 | 允许复查原始证据，不复制整份输出 |
| 当前归因 | 主约束、判别实验、反例与未解释现象 | 限定候选机制和证伪条件 |
| 守护条件 | 正确性、质量、失败率、容量、SLO 与回归阈值 | 阻止局部收益掩盖退化 |
| 行动状态 | `inspect`、`optimize`、`validate` 或 `revert` | 决定补测、选候选、组合复测或回退 |
