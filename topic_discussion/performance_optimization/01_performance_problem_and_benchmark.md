# 01 性能问题与比较契约

## 本节导读

“训练变慢”“显存不够”或“服务延迟升高”都不是可以直接优化的问题。只有明确模型、输入分布、运行环境、目标指标和不可破坏的约束，才能判断候选相对基线是否真的改善了目标工作负载。

本节建立基线与候选的比较条件，并用失败状态和停止条件排除无效运行。完成后，学习者能够判断两组结果是否可以比较，以及一次实验是否值得继续复测。

## 什么条件下两个结果可以比较

| 要素 | 需要固定或记录的内容 | 缺失时会发生什么 |
|:---|:---|:---|
| 工作负载 | 模型、任务、输入长度、批量、并发、输出长度与数据分布 | “更快”可能只来自更轻的输入 |
| 环境 | 硬件、软件版本、执行后端、数据类型、并行与缓存状态 | 结果无法复现，也无法归因 |
| 指标 | 训练单步时间、吞吐与峰值显存；推理 TTFT、TPOT、P99 与并发 | 平均耗时掩盖尾延迟或容量问题 |
| 对照 | 基线、候选、预热、重复次数和原始样本 | 单次波动被误写成优化收益 |
| 守护条件 | 正确性、质量、安全、SLO 与预算 | 性能提升可能以不可接受的退化换来 |

训练、推理和多卡运行可以使用不同指标，但比较顺序相同：先固定条件，再计算候选相对基线的变化，最后检查守护条件。[性能分析专题](../performance_analysis/intro.md)提供计时、执行轨迹、显存时间线和噪声判断方法。

## 基线与候选需要固定哪些条件

| 字段组 | 基线与候选必须共享的内容 | 允许变化的内容 |
|:---|:---|:---|
| 运行身份 | 模型版本、数据版本、硬件、软件栈、随机种子 | 候选配置及其明确依赖 |
| 工作负载 | 样本集合、长度分布、批量或并发、生成上限 | 为敏感性分析预先定义的单一变量 |
| 测量方法 | 预热、重复、同步位置、计时区间、显存口径 | 不允许临时改变 |
| 结果记录 | 原始样本、汇总统计、失败状态、质量结果 | 基线与候选使用不同结果标签 |
| 停止条件 | OOM、数值异常、质量越界、未命中目标执行路径 | 不允许候选绕过 |

不同问题还需要保留各自的最小证据。容量问题记录对象和峰值，I/O 问题记录传输是否暴露在关键路径上，时间问题记录阶段时间和总时间；这些字段可以不同，但必须属于同一运行身份。

## 无效运行、守护条件与停止条件

| 观察 | 为什么不能形成性能结论 | 处理方式 |
|:---|:---|:---|
| 基线与候选的输入长度或批量不同 | 工作量已经改变 | 重新构造同一工作负载 |
| 首次运行与稳态运行混在一起 | 编译、加载或缓存开销污染对照 | 分开记录冷启动、预热和稳态 |
| 候选回退到另一执行路径 | 测到的不是目标机制 | 保存执行路径证据并停止准入 |
| 仅保存中位数或单次结果 | 无法判断波动、离群值和失败比例 | 保存原始配对样本 |
| 正确性或质量越过门槛 | 性能收益不可采用 | 记录失败并回退候选 |
| 资源不足导致 OOM 或请求拒绝 | 缺少可比较的候选结果 | 保存失败阶段、容量和配置，不用缺失值代替结果 |
