# 04 · SFT 实验、产物与交付

一条 SFT 基线只有在训练、评测、恢复和交付都能复查时，才能成为 DPO、GRPO 或部署对照的起点。它消费第 13 节的监督损失契约和第 15 节的有效更新结果，既输出后续适配方案复用的产物，也提供是否升级到偏好或奖励优化的证据。

## 最小实验闭环

`数据版本 → 模型 / 分词器 → 适配器配置 → 训练控制 → 独立评测 → 检查点 / 产物 → 报告`

| 交付对象 | 至少保存什么 | 用途 |
|:---|:---|:---|
| 训练恢复 | 模型 / 适配器、优化器、调度器、全局步数、随机种子 | 确认恢复属于同一训练线 |
| 推理复现 | 分词器、特殊 Token、聊天模板、生成配置 | 防止训练与推理行为漂移 |
| 配置与数据 | 训练、LoRA 与评测配置，数据版本与切分 | 解释结果来自什么条件 |
| 证据与报告 | 训练 / 验证指标、样例、资源、失败与结论 | 比较基线与候选 |

## SFT 何时完成，何时升级

SFT 的作用是用示范高效建立任务接口、输出格式、指令遵循和基础正确性。它通常为后续偏好或奖励优化提供稳定初始化、可比较基线和参考策略来源，但不是形式上的强制步骤：已有指令模型若通过相同门槛，可以直接进入偏好分支；知识缺失主要来自外部事实或领域表示时，应先比较 RAG 或持续预训练。

进入后续阶段前需要同时检查行为基线、继续监督学习的边际收益、剩余失败类型和反馈质量。奖励分布不追求均匀，而要能区分候选：覆盖率足够，同分率和饱和率可控，正负或组内差异能够产生稳定优势，并与冻结评测或人工抽检同向。高质量示范仍容易获得且 SFT 继续稳定提升时，不应只因为“可以做 RL”就升级。进入 DPO 时，SFT 检查点通常同时提供策略初始化和冻结参考策略的来源；进入 GRPO / RL 时，至少记录模型版本、分词器、数据、训练配置和通过的评测。只有损失下降而没有这些产物，不能构成可复用基线。

| 观察到的证据 | 优先动作 | 不直接升级的原因 |
|:---|:---|:---|
| 格式、任务接口或指令遵循仍不稳定 | 补数据并继续 SFT | 奖励会同时承担“教会基本行为”和“优化偏好”两种职责 |
| 独立质量仍随高质量示范稳定提升 | 继续 SFT，并检查数据覆盖与训练控制 | 尚未出现监督学习平台期 |
| 已有同提示优选 / 非优选回答，不需要策略探索 | 使用 DPO 等离线偏好优化 | 负反馈不等于必须建立在线 RL 系统 |
| 需要当前策略探索多步轨迹，反馈来自偏好模型 | 评估 PPO 等在线策略更新 | 需要轨迹、价值或基线、策略版本与回滚控制 |
| 数学答案、代码测试或环境终态可验证，候选间奖励可区分 | 评估 GRPO / RLVR | 规则覆盖不足或奖励饱和时容易产生奖励投机 |
| 奖励大量同分、全正 / 全负，或与独立成功率背离 | 修复奖励、验证器或采样分布 | 缺少可学习的相对信号 |
